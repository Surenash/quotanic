# Notes & Observations

**Freeform Observations:**
- The `manfacquot/index.tsx` file is exceptionally large (~240KB) and has a backup (`index.tsx.bak`). This strongly suggests it's a prime candidate for refactoring into smaller, modular React components.
- The presence of scripts like `simulate_pricing.py`, `test_matcher.py`, and `fix_pricing_structure.py` indicates that the core business logic around the FBM engine is actively being tuned and tested.
- The application uses AWS for deployment: Frontend on AWS Amplify (`amplify.yml`), and Backend (Django, Celery, Redis, PostgreSQL) on a single EC2 instance (`t3.micro`) using `docker-compose.prod.yml`.
- The `AGENTS.md` file defines explicit instructions for AI agents working on the project, particularly regarding the Django API structure (`/api/designs/`, `/api/orders/`, etc.) and Celery integration.
- CAD uploads use a direct-to-S3 pattern via pre-signed URLs generated by the Django backend.
- The `FBM/README.md` shows the engine is highly sophisticated (FBM_advanced.py) with 40+ feature types detected, pattern recognition, and optimization strategies.

**Things to Revisit:**
- The relationship and communication between the standalone `front end` AI Studio and the main `manfacquot` application.
- Ensuring the memory-constrained `t3.micro` EC2 instance can handle the heavy `python-occ-core` / FBM computations via Celery.
